# Mac Catalyst 与 iCloud 本地优先生日应用设计规格

- 日期：2026-09-04
- 状态：规格已确认，等待书面规格复核
- 适用项目：`birthday`
- 移动端版本：iOS 1.1（iPhone，延续现有 iOS 17 及以上范围）
- 桌面端版本：macOS 1.0（Mac Catalyst，macOS 14 及以上）
- 发布形态：与现有 iOS App 共用 App Store 应用记录和 Bundle ID

## 1. 背景与目标

“岁时·农历生日提醒”已经以 iPhone 本地离线应用发布。当前工程只有 iOS 应用目标，业务核心位于支持 iOS 17 和 macOS 14 的 `BirthdayCore` Swift Package；SwiftUI 应用层仍包含 `UIKit`、`UIApplication`、iPhone 文案、标签栏导航和移动端尺寸假设，不能直接视为正式桌面应用。

本期增加一个正式的 Mac Catalyst 平台版本，并在 iPhone 与 Mac 之间加入 iCloud 私有数据库同步。产品仍坚持本地优先：本地 SwiftData 是每台设备的运行时事实来源，查看、搜索、增删改、农历换算、应用锁和本地提醒均不得等待 iCloud 或自有服务器。iCloud 只承担同一 Apple ID 设备之间的可选同步，默认开启并允许每台设备独立关闭。

### 1.1 成功标准

1. iPhone 和 Mac 在断网、未登录 iCloud 或 iCloud 故障时均可完整使用核心功能。
2. 已发布 iPhone 版本的本地数据从当前 V2 数据库迁移后全部保留，不重建数据库。
3. 同一 Apple ID 下，iPhone 与 Mac 可以增量同步生日的新增、修改和删除。
4. 关闭 iCloud 后保留本机数据和尚未发送的修改；重新开启后继续增量同步。
5. 并发编辑和删除冲突不静默丢弃内容，用户可以选择保留本机或 iCloud 版本。
6. Mac 版具备适合窗口、鼠标和键盘的桌面布局，不是放大的手机界面。
7. iOS 1.1 与 macOS 1.0 在生产 CloudKit 环境完成真实双端验证后，才允许提交审核。
8. 用户可以从设置中导出本机可见的完整生日数据，满足 CloudKit 用户数据访问要求。

## 2. 已确认的产品决策

1. 正式桌面路线采用 Mac Catalyst，不使用“在 Apple 芯片 Mac 上直接运行 iPhone App”的快速兼容路线。
2. 本地 SwiftData 始终是权威数据源，iCloud 不成为启动或保存操作的前置条件。
3. iCloud 同步默认开启，在设置中可以按设备关闭或重新开启。
4. 同步使用 `CKSyncEngine` 和 CloudKit 私有数据库，不使用 SwiftData 自动 CloudKit 托管。
5. 首版 Mac 计划同时支持 Apple 芯片与 Intel Mac，最低 macOS 14。
6. Mac 保持“现代空气感”、日历优先和原生分组表单的视觉方向。
7. 首版只提供一个主窗口，不加入多窗口、家庭共享、协同编辑、小组件或 Android 客户端。
8. iCloud 同步不复用或启用现有生日服务器；服务器不可用与本期客户端能力无关。

## 3. 平台与发布边界

### 3.1 Xcode 目标

工程保留现有 iOS 目标，并新增独立 Mac Catalyst 应用目标。两个目标共享：

- `BirthdayCore` 领域、存储、通知规划和安全能力
- 通用 SwiftUI 功能视图及设计令牌
- 数据迁移方案和 CloudKit 同步适配层
- 隐私清单中共同适用的声明

Mac 目标单独拥有：

- 桌面根导航、窗口尺寸和工具栏
- 菜单命令、键盘快捷键和右键菜单
- Mac 专用设置文案、Touch ID 文案和系统设置入口
- Mac App Store 图标、截图和平台元数据

两个平台使用同一 Bundle ID，以现有 App Store 应用记录增加 macOS 平台并形成通用下载。iOS 与 macOS 可以使用不同的版本号和构建号，本期计划为 iOS 1.1 与 macOS 1.0。

两个发布目标都需要增加 iCloud/CloudKit 能力与用于接收 CloudKit 变更的远程通知后台模式。远程通知只作为系统同步信号，不承载生日正文，也不改变生日提醒由本地通知负责的边界。现有 Release 中“无后台同步权限”的配置将随 iOS 1.1 明确升级，且必须同步更新隐私材料和审核说明。

### 3.2 明确不做

- 不把现有 iPhone 二进制直接开放为 Apple 芯片 Mac 兼容版
- 不将服务器同步入口重新暴露给 App Store Release
- 不使用 CloudKit 公共数据库或多人共享数据库
- 不同步界面状态、通知权限、设备级开关或派生日期缓存
- 不在本期原生适配 iPad，也不扩展 Android
- 不承诺 iCloud 实时同步或后台到达时间

## 4. 总体架构

```text
iPhone SwiftUI -> 本地 SwiftData <- CKSyncEngine -> iCloud 私有数据库
                         ^                              |
                         |                              v
Mac Catalyst UI -> 本地 SwiftData <- CKSyncEngine -----+

每台设备的本地 SwiftData -> 农历计算 -> 本机通知中心
```

应用分为以下边界：

1. **共享领域层**：生日验证、农历换算、日期投影和提醒候选生成。
2. **共享本地数据层**：SwiftData 模型、事务、迁移、软删除和本地查询。
3. **iCloud 同步层**：CloudKit 编解码、`CKSyncEngine` 生命周期、增量状态、账号检测、重试和冲突保存。
4. **通知层**：按设备请求权限、维护通知窗口和展示通知健康状态。
5. **平台适配层**：封装 UIKit/AppKit 差异、系统设置链接、显著时间变化事件和设备名称。
6. **SwiftUI 界面层**：共用业务视图，分别提供 iPhone 标签栏根界面与 Mac 分栏根界面。

所有用户写操作先在一个本地事务中完成。同步层只能读取已提交的本地变化并把远端结果合并回本地数据库；任何 CloudKit 错误都不得回滚已成功的本地保存。

## 5. Mac 桌面界面与交互

### 5.1 主窗口

默认窗口约为 1080 × 720 点，最小尺寸约为 820 × 600 点，支持自由缩放、全屏和系统窗口恢复。首版只有一个主窗口，避免同一生日在多个窗口中并发编辑。

使用三栏 `NavigationSplitView`：

1. **侧边栏**：日历、全部生日、设置；发生冲突时增加带数量徽标的“同步冲突”。
2. **主内容区**：默认展示月历、日期选择和当天生日；“全部生日”展示可搜索列表。
3. **详情栏**：展示选中生日、下一次阳历日期、提醒安排及编辑和删除操作。

窗口收窄时详情栏先收起为两栏；不得通过压缩月历单元格造成不可读布局。

### 5.2 工具栏与输入

工具栏提供上个月、下个月、今天、搜索和新增。支持：

- `Command-N`：新增生日
- `Command-F`：搜索
- `Command-,`：打开设置
- `Delete`：删除选中记录并二次确认
- 双击记录：编辑
- 右键菜单：编辑、删除

设置页提供“导出生日数据”，使用系统分享面板或保存面板导出 UTF-8 JSON 文件。导出只读取本机已合并的数据，不为导出操作强制等待 iCloud；文件包含导出时间、格式版本和所有未删除生日，不包含同步令牌、账号标记、冲突内部快照或通知授权状态。

新增和编辑使用居中的原生表单窗口，延续“基本信息、提醒、补充信息”的分组结构。提交失败时保留输入并定位到错误分组。

### 5.3 视觉与辅助功能

继续使用雾白、潮汐青和月光金设计令牌，保留浅色、深色、减少透明度和动态字体适配。Mac 增加清晰的悬停、选中和键盘焦点状态。所有图标按钮提供文字标签或辅助功能名称，不只用颜色表达同步和错误状态。

## 6. iCloud 数据设计

### 6.1 CloudKit 记录

每条生日使用现有 UUID 生成稳定的 CloudKit Record ID。私有记录同步：

- `id`
- `name`
- `lunarMonth`
- `lunarDay`
- `isLeapMonth`
- `reminderTimeMinutes`
- `notifyDayBefore`
- `notifySameDay`
- `createdAt`
- `updatedAt`
- `deletedAt`
- 冲突检测需要的修改标识

以下字段不上传：

- `nextSolarDate`：按设备时区重新计算
- 通知权限、已安排数量和设备通知开关
- 当前标签、选中日期、窗口尺寸等界面状态
- iCloud 同步开关和账号指纹
- 服务器 `version`、游标、旧服务器同步队列和错误状态
- 当前 Release 未暴露的邮件地址、邮件内容和服务器绑定数据

删除使用带 `deletedAt` 的墓碑记录，不立即物理删除 CloudKit 记录。数据量很小，首版不自动清理墓碑；后续若加入清理，需要单独设计多设备确认机制。

### 6.2 本地模型

数据库从 V2 增加到 V3。V3 增加 iCloud 同步状态、持久化的 `CKSyncEngine` 状态及必要的冲突元数据，但保留现有生日实体、服务器同步操作、服务器游标和冲突记录，避免破坏历史数据或未来迁移能力。

iCloud 使用独立的同步适配与状态实体，不直接套用服务器的 `baseVersion`、单调游标和上传结果语义。可以复用通用的冲突展示模型，但不能让两套同步协议共享同一运行队列。

同步开关存储为设备本地设置，首次不存在时默认 `true`。该开关自身不进入 iCloud。

### 6.3 首次迁移与初始合并

升级后的启动顺序：

1. 完成 V2 到 V3 本地轻量迁移并打开界面。
2. 重新计算本机 `nextSolarDate`，恢复本地提醒能力。
3. 检测 iCloud 账号状态；不可用时保持本地模式。
4. iCloud 可用且同步开关开启时，创建或恢复同步引擎。
5. 拉取私有记录并与本机生日按 UUID 合并。
6. 把仅存在于本机的生日和墓碑加入上传队列。
7. 合并事务完成后重新加载界面并重建本地通知。

初次同步只做集合合并，不允许用空云端覆盖本机，也不因姓名相同自动合并不同 UUID 的生日。

### 6.4 增量同步

本地保存、软删除和冲突解决完成后，将对应 Record ID 标记为待发送。`CKSyncEngine` 在系统条件允许时推送与拉取变化；应用启动、回到前台、联网恢复和用户手动刷新时也可以请求一次同步。

同步层必须持久化引擎状态并从状态更新事件中安全恢复。同步回调只把远端变更写入本地数据库；界面始终观察本地数据，不直接观察 CloudKit。

## 7. 冲突、删除与账号变化

### 7.1 冲突规则

- 只有一端自共同基础后发生修改时，自动采用该修改。
- 本机与 iCloud 同时修改同一 UUID 时，保存双方完整快照并把记录标记为冲突。
- 冲突界面提供“保留本机”和“使用 iCloud”两个明确选择。
- 选择结果作为新的完整版本提交，解决前不静默覆盖任一方。
- 删除与编辑冲突显示“恢复并保留编辑”或“确认删除”。
- 不同 UUID 即使姓名和生日相同也只作为潜在重复项提示，不自动删除。

### 7.2 同步开关

关闭同步后：

- 停止 CloudKit 上传、下载和后台同步
- 保留本机数据、同步引擎状态和尚未发送的修改
- 不删除 iCloud 数据
- 本机 CRUD、农历换算、应用锁和通知继续工作

重新开启后从持久化状态增量恢复；如果状态不可恢复，则进行安全的全量枚举与按 UUID 合并，而不是清空任一侧。

### 7.3 iCloud 账号变化

应用保存不可逆的本地账号标记或哈希，不记录可展示的完整 Apple 账号标识。检测到账号退出、受限或空间不足时暂停同步并保留队列。

检测到 iCloud 账号更换时暂停上传，展示一次明确选择，只有用户确认后才把本机数据合并到新账号的私有数据库。取消时保持本地模式，避免把私人生日误传到另一个账号。

## 8. 本地通知

iPhone 与 Mac 分别请求通知权限并维护各自通知计划。iCloud 同步提醒规则，但不同步通知权限、设备通知开关和已经安排的系统请求。

每台设备提供“在此设备接收提醒”开关。用户在两台设备都启用时，同一生日会在两台设备各提醒一次，这是预期行为。

继续使用最近 60 条业务通知加一条维护提醒的滚动窗口，并在以下时机重建：

- 启动和回到前台
- 本地新增、修改或删除
- iCloud 合并完成
- 日期或时区变化
- 系统提供的后台刷新机会

CloudKit 远程通知只用于唤醒数据同步，不直接展示为生日提醒。生日提醒始终由本地通知中心安排，避免依赖服务器或云端准时到达。

## 9. 应用锁与生命周期

安全层继续使用 `LocalAuthentication` 的设备所有者验证策略，并把能力显示改为平台无关的生物识别类型：

- iPhone：Face ID 或设备密码
- Mac：Touch ID 或登录密码

应用不读取或保存生物识别数据。Mac 在普通窗口切换或短暂失去焦点时不重复锁定；在系统锁屏、休眠或重新启动应用后锁定。认证失败只阻止查看本地资料，不取消已安排的通知。

UIKit 专用能力必须收口到平台适配层，包括系统设置 URL、设备名称、显著时间变化事件和动态系统颜色。共享 SwiftUI 视图不得无条件导入 UIKit。

## 10. 隐私与安全

- 生日资料只存储在本机和用户自己的 CloudKit 私有数据库。
- 不接入广告、统计 SDK 或第三方云服务。
- 不要求注册应用账号，不向现有生日服务器上传本期 App Store Release 数据。
- 日志不得记录姓名、生日、邮件内容、CloudKit 记录正文或完整账号标识。
- CloudKit 同步状态只展示用户可操作的信息，不泄露底层令牌或容器标识。
- 更新应用内隐私政策、公开隐私页面、支持页面、设置页、App Store 隐私问卷和审核说明。
- 删除或替换“仅保存在此 iPhone”等不再准确的文案，统一说明“本机优先保存；启用 iCloud 后通过用户的 iCloud 私有数据库同步”。
- CloudKit 容器从开发环境部署到生产环境前，必须核对 Record Types、索引和权限；生产 Schema 部署属于发布动作，需要单独确认。

## 11. 状态与错误处理

设置页使用以下用户状态：

- 已同步
- 正在同步
- 本地有待同步修改
- iCloud 未登录
- iCloud 空间不足
- iCloud 暂不可用
- 同步已关闭
- 需要处理冲突

行为规则：

| 情况 | 行为 |
| --- | --- |
| 未登录 iCloud | 保持本地使用，不循环弹窗 |
| 网络中断 | 本地保存成功，排队等待恢复 |
| iCloud 空间不足 | 保留待同步修改并展示可恢复状态 |
| 容器或权限错误 | 暂停同步，提供重试和诊断类别 |
| 多端冲突 | 保存双方版本，等待用户选择 |
| 通知权限关闭 | 数据正常使用，引导打开系统设置 |
| 本地数据库失败 | 不启动同步，展示安全重试页 |
| iCloud 账号更换 | 暂停上传，等待用户确认新账号 |

界面不得显示虚假的“实时”“已备份”或“同步成功”。只有本地已落盘、引擎无待处理修改且最近一次拉取完成时，才能显示“已同步”。

## 12. 测试与验收

### 12.1 数据与迁移

- 使用固定 V1/V2 SQLite 夹具验证到 V3 的升级
- 验证生日、提醒、墓碑、旧服务器队列和游标完整保留
- 模拟迁移失败和重新启动，确保可重试且不重复
- 验证派生日期在不同时区重新计算，不上传旧缓存

### 12.2 离线与开关

- 飞行模式、DNS 失败、iCloud 未登录和 CloudKit 错误下完整 CRUD
- 关闭同步后重启，确保设置和本机数据保持
- 关闭期间连续编辑，再开启后顺序与最终结果正确
- 同步失败不得把本地保存结果改为失败

### 12.3 双端同步

- 使用真实 iPhone 与 Mac 验证新增、修改、删除和恢复
- 验证断网编辑、重新联网、重复回调和应用强制退出
- 验证同记录并发修改和删除冲突
- 验证旧设备不会复活墓碑记录
- 验证账号退出、空间不足、账号切换和拒绝迁移到新账号

### 12.4 通知与安全

- 两台设备分别开启或关闭通知
- 验证 iCloud 合并后通知窗口重建
- 验证应用退出后已安排的 Mac 通知仍可显示
- 验证 iPhone Face ID、Mac Touch ID 及密码回退
- 验证 Mac 窗口切换不触发不合理的重复锁定

### 12.5 界面与构建

- iPhone 与 Mac Catalyst Debug、Release 构建
- Mac Apple 芯片与 Intel 架构检查
- 键盘导航、快捷键、右键、窗口缩放和全屏
- 浅色、深色、减少透明度、动态字体和 VoiceOver
- 隔离的虚构数据 UI 测试与 App Store 截图
- iPhone 分享面板与 Mac 保存面板的数据导出验证
- 最终归档的签名、权限、隐私清单和包内容检查

## 13. 发布方案与操作门禁

### 13.1 计划版本

- iOS：1.1，加入 iCloud 同步和相应设置界面
- macOS：1.0，首次 Mac Catalyst 发布

### 13.2 发布顺序

1. 完成实现、单元测试和本地构建。
2. 在 CloudKit 开发环境执行真实 iPhone 与 Mac 双端测试。
3. 更新隐私政策、支持页面、隐私问卷草稿和审核说明。
4. 经确认后部署 CloudKit 生产 Schema。
5. 在现有 App Store Connect 应用中增加 macOS 平台。
6. 归档并上传 iOS 1.1 与 macOS 1.0。
7. 完成双平台 TestFlight 真实安装验证。
8. 补齐 Mac 截图、描述、兼容信息和审核路径。
9. 经行动时确认后选择构建并提交审核。
10. 审核通过后分别验证中国大陆商店页面、兼容设备与真实下载安装。

首次 Mac 发布的自动或手动发布方式在提交前单独确认，不沿用旧版本的选择。

### 13.3 必须再次确认的外部动作

以下操作不包含在设计确认中，执行前必须获得当时的明确授权：

- 创建或修改生产 CloudKit 容器和 Schema
- 修改线上隐私或支持页面
- 创建 App Store Connect 的 macOS 平台记录
- 创建发布证书、描述文件和生产签名归档
- 上传构建、选择构建、配置发布方式
- 提交 App Review、回复审核或重新提交

“已构建”“已上传”“TestFlight 可用”“已提交”“等待审核”“已批准”和“公开可下载”必须分别报告，不得混用。

## 14. 实施完成定义

只有满足以下条件，才能称为本期实现完成：

1. 所有新增和现有自动化测试通过。
2. 固定数据库夹具迁移测试通过，且没有重生成旧夹具。
3. iPhone 与 Mac 在无网络和无 iCloud 条件下完整可用。
4. CloudKit 开发与生产环境分别完成真实双端同步验证。
5. Mac 界面通过窗口、键鼠、Touch ID 和辅助功能验收。
6. 隐私材料、应用内文案、实际网络行为和 App Store 问卷一致。
7. 最终上传包经过签名、权限和 Payload 检查。
8. App Store Connect 状态和公开商店状态分别经过实时验证。
